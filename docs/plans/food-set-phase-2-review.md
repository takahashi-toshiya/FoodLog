# 食品セット 第2段階レビュー用メモ

このファイルは、食品セット機能の第2段階「セットの登録・編集」の実装意図を伝えるための一時的なレビュー資料である。

## 今回実装した範囲

- セット名、食品、摂取倍率の入力と検証
- ライブラリ食品を複数選択するフォーム
- 食品セットの登録画面と編集画面
- Expo Routerの登録・編集ルート
- 入力検証と主要な画面操作のテスト

ライブラリのセット一覧、セット削除、食事への一括追加はまだ実装していない。

## 実装意図

### 登録と編集で`FoodSetForm`を共有した理由

セット名、食品選択、倍率入力、エラー表示、保存中の制御は両画面で同じ振る舞いになるため。登録画面と編集画面は、初期値とRepositoryへ渡す操作だけを担当する。

### フォーム状態で`FoodItem`を保持する理由

編集中は食品名、基準量、PFCを表示する必要があるため、食品IDだけでなく取得済みの`FoodItem`を保持する。保存前に`validateFoodSetInput`で、Repositoryが必要とする食品IDと倍率だけへ変換する。

### 既存の`FoodSelectionModal`を再利用した理由

食品の取得、検索、空状態、取得失敗という既存の振る舞いを重複実装しないため。モーダルで食品を1件ずつ選び、フォーム側に選択済み食品を蓄積する構成にした。

### 重複をUIとサービスの両方で防ぐ理由

UIでは同じ食品を再選択した時点で利用者へ伝え、サービスではUI以外から値が渡された場合も保存前に拒否する。DBの一意制約は最後の防御として残している。

### 入力検証をサービスへ置いた理由

セット名、食品件数、倍率、重複は画面表示ではなく保存可能なセットの条件であるため。React Nativeへ依存しない関数にし、境界値を画面操作なしで確認できるようにした。

### 食品の削除を保存時まで確定しない理由

フォーム上の「削除」は編集中の配列から外すだけにしている。保存するまではDBを変更しないため、キャンセルすれば元のセットが維持される。

### ルートだけ先に追加した理由

登録・編集画面をExpo Routerから開ける境界を用意するため。ライブラリからの導線は第3段階で接続するので、現時点では通常操作から画面へ遷移しない。

## 特に伝わりにくそうな箇所

- `FoodSetInputValues`は画面表示用に`FoodItem`と文字列の倍率を持つ
- `CreateFoodSetInput`は保存用に食品IDと数値の倍率だけを持つ
- 編集画面ではRepositoryの`FoodSet`を`createInitialValues`でフォーム形式へ変換している
- 倍率は空文字、0、負数、数値以外を拒否し、小数は許可している
- 食品の並び順はフォーム配列の順番であり、第2段階では並び替え操作を提供しない

## テストで確認している範囲

- セット名の前後空白を除去して保存形式へ変換できること
- セット名なし、食品0件、不正倍率、重複食品を拒否すること
- 食品を選択し、倍率を変更して登録できること
- 同じ食品を再選択しても重複せず、既存の倍率を維持すること
- 保存済みのセットを初期表示し、名前と倍率を更新できること
- 全食品を外した状態では更新できないこと
- 存在しないセットでは編集フォームを表示しないこと

見た目、キーボード操作、長い食品名、小さい画面でのスクロールは自動テストの対象外であり、ライブラリへ導線を接続した後にExpo Goで確認する。
