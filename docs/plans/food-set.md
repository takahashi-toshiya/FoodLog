# 食品セット機能 実装計画

## 目的

複数のライブラリ食品と摂取倍率をセットとして保存し、指定した日付・食事区分へまとめて記録できるようにする。

GitHub Issue #13 の完了を対象とする。

## 今回の実装範囲

- 食品セットを登録・編集・削除する
- セット名、食品、食品ごとの摂取倍率を設定する
- ライブラリの「セット」タブに登録済みセットを表示する
- セットの内容と合計カロリー・PFCを確認する
- 日付と食事区分を指定し、セット内の食品を食事記録へ一括追加する
- セットと食事記録をSQLiteへ保存する
- 一括追加を1つのトランザクションで実行する
- 読み込み中、空状態、取得失敗、保存失敗を表示する

## 対象外

- 1つのセット内で食品ごとに異なる日付・食事区分を指定すること
- セット内への自由入力食品の追加
- セットの複製、並び替え、カテゴリ分け
- クラウド同期、共有、外部食品データベースとの連携

## 仕様

### セットの登録・編集

- セット名は必須とする
- セットには1件以上のライブラリ食品を登録する
- 同じ食品は1つのセットへ重複登録しない
- 食品ごとに0より大きい摂取倍率を設定し、初期値は`1`とする
- 食品の表示順はセットへ追加した順とする
- 編集では、セット名、食品の追加・削除、摂取倍率を変更できる
- 保存中の多重操作を防ぎ、失敗時は入力内容を維持する

### ライブラリ表示

- 「セット」タブを選択すると、登録済みセットの一覧を表示する
- セットには、セット名、食品数、現在の食品情報から算出した合計カロリー・PFCを表示する
- セット本体を押すと、食事への一括追加画面を開く
- メニューから編集・削除を選べる
- セットが0件の場合は、セット登録へ進める空状態を表示する
- ヘッダーの追加ボタンは、選択中のタブに応じて食品登録またはセット登録を開く
- 食品名検索は「よく使う食品」だけを対象とし、セットタブでは表示しない

### 食事への一括追加

- 追加画面でセット内容、日付、食事区分を確認する
- 日付の初期値は当日、食事区分の初期値は朝食とする
- 指定した日付と食事区分を、セット内の全食品へ共通で適用する
- 各食品のPFCへセットの摂取倍率を反映し、カロリーはPFCから算出する
- 食事記録には、追加時点の食品名、PFC、カロリー、メモを保存する
- 食事記録の`source_food_id`には元の食品IDを保存する
- 食事記録からセット自体は参照しない
- 一括追加後にセットや食品を変更しても、過去の食事記録は変更しない
- すべての食事記録を保存できた場合だけ成功とし、途中で失敗した場合は全件を取り消す
- 保存成功後は、追加先の日付を指定してToday画面へ移動する

## データベース変更

スキーマバージョンを`3`へ更新し、次のテーブルを追加する。実装時に`docs/database-design.md`も同じ内容へ更新する。

### `food_sets`

- `id`
- `name`
- `created_at`
- `updated_at`

### `food_set_items`

- `id`
- `food_set_id`
- `food_id`
- `serving_multiplier`
- `sort_order`
- `created_at`
- `updated_at`

制約は次のとおりとする。

- `food_set_id`は`food_sets.id`への外部キーとし、セット削除時は項目も削除する
- `food_id`は`foods.id`への外部キーとする
- `serving_multiplier`は0より大きい値に限定する
- `sort_order`は0以上に限定する
- `(food_set_id, food_id)`を一意にし、同じ食品の重複を防ぐ

## 保存処理の構成

### 食品セット

`FoodSetRepository`と`SQLiteFoodSetRepository`を追加し、画面からSQLiteを直接操作しない。

```text
食品セット画面
    ↓
FoodSetRepository
    ↓
SQLiteFoodSetRepository
    ↓
food_sets / food_set_items / foods
```

Repositoryは次の操作を提供する。

- 一覧取得
- IDによる詳細取得
- セットと項目の一括登録
- セットと項目の一括更新
- セット削除

登録と更新は、親となるセットとすべての項目を1つのトランザクションで保存する。

### 食事の一括追加

`MealRepository`へ複数件を一括保存する操作を追加する。`SQLiteMealRepository`は、すべての`meal_entries`を1つのトランザクション内で追加する。

セットから食事入力を生成する処理は`meals/services/`へ置き、画面やSQLiteへ依存させない。

## 起こりそうな失敗

- セット本体だけ保存され、項目の一部が保存されない
- 編集時に古い項目が残る、または表示順が変わる
- 摂取倍率が合計値や食事記録へ二重に適用される
- 一括追加の途中で失敗し、一部の食事だけが残る
- 食品やセットの編集によって、過去の食事記録まで変わる
- 削除済みの食品を含むセットを追加しようとして失敗する
- タブ切り替え後に食品用の検索欄や追加処理がセット画面へ残る
- 保存後にToday画面が追加先とは異なる日付を表示する

## テスト計画

### サービス

- セット名、食品0件、不正な摂取倍率を検証できる
- 同じ食品の重複を検知できる
- 各食品の倍率を1回だけ適用し、正しいPFCとカロリーの食事入力を生成できる
- `0.5`、`1`、`2`の倍率で正しく計算できる
- 全項目へ同じ日付と食事区分を設定できる

### ストレージ

- セットと複数項目を保存し、同じ順序で取得できる
- セット名、食品構成、倍率を更新できる
- セットを削除すると項目も削除される
- 重複食品や不正な倍率をDB制約でも拒否できる
- 食事を複数件まとめて保存できる
- 一括追加の途中で失敗した場合、食事が1件も残らない
- 既存スキーマからバージョン3へ移行しても既存データが残る

### 画面

- セットタブで一覧、空状態、読み込み失敗を表示できる
- 選択中のタブに応じて追加ボタンの遷移先が変わる
- セットへ食品を追加・削除し、倍率を変更して保存できる
- 既存セットを編集・削除できる
- セットを選び、日付と食事区分を指定して一括追加できる
- 保存失敗時に入力内容を維持し、再試行できる
- 保存成功後に追加先の日付のToday画面へ移動する
- 既存の食品CRUD、食品検索、単品の食事追加が引き続き動作する

### 手動確認

- Expo Goでセット登録、編集、削除、一括追加を一連で操作できる
- 小さい画面とキーボード表示中でも、食品一覧と倍率入力を操作できる
- iOSとAndroidでモーダル、確認ダイアログ、戻る操作に問題がない
- 一括追加後にToday画面の明細と合計値が正しい

## 段階的な実装方針

食品セット機能全体はIssue #13とこの実装計画で管理し、実装・テスト・レビュー・コミットの完了単位を次の4段階に分ける。原則として、前段階のレビューが完了してから次へ進む。

機能全体で1つのブランチとPull Requestを使用し、各段階を個別のコミットとして残す。

### 第1段階：DB・Repository

- 未決定の削除仕様を確定する
- `food_sets`と`food_set_items`をDB設計書へ追加する
- スキーマバージョン3のマイグレーションを実装する
- 食品セットの型を定義する
- `FoodSetRepository`と`SQLiteFoodSetRepository`を実装する
- 登録、取得、更新、削除、トランザクション、DB制約をストレージテストで確認する

この段階では画面を実装しない。データ構造と保存境界が、後続の機能を支えられることをレビューする。

### 第2段階：セットの登録・編集

- セット入力の型と検証処理を実装する
- 食品の複数選択と摂取倍率の入力UIを実装する
- セット登録画面と編集画面を実装する
- 読み込み、保存、入力エラーを扱う
- 入力検証と登録・編集の主要操作をテストする

この段階では、セットの内容を正しく作成・変更できることをレビューする。

### 第3段階：ライブラリのセット一覧

- ライブラリの「セット」タブへ保存済みセットを表示する
- セットカード、合計カロリー・PFC、空状態、取得失敗を実装する
- 選択中のタブに応じて追加ボタンの遷移先を切り替える
- セットの編集・削除導線を接続する
- 一覧取得、タブ切り替え、削除、既存食品機能の回帰をテストする

この段階では、ライブラリ内でセットを管理でき、既存の食品一覧へ影響がないことをレビューする。

### 第4段階：食事への一括追加

- セットから食事入力を生成するサービスを実装する
- `MealRepository`へトランザクション付き一括追加を実装する
- 日付と食事区分を指定する一括追加画面を実装する
- 保存成功後に追加先の日付のToday画面へ移動する
- 倍率計算、全件成功または全件取り消し、過去記録の維持をテストする
- 既存機能を含めてFormat、Lint、型チェック、テスト、ビルド、実機確認を行う

この段階のレビュー完了をもってIssue #13全体の完了とし、Pull Requestを作成する。

## 決定事項

### セットで使用中の食品を削除する場合

セットから食品を先に外すまで、ライブラリ食品の削除を拒否する。セット内容が利用者の意図なく変わることを防ぐため、`food_set_items.food_id`を`ON DELETE RESTRICT`とする。

利用者向けの「この食品はセットで使用中です」というエラー表示は、セット管理をライブラリへ接続する第3段階で実装する。

## 完了条件

- Issue #13の受け入れ条件をすべて満たす
- セットの登録・編集・削除と、食事への一括追加を実機で完了できる
- 一括追加に失敗した場合、食事記録が部分的に残らない
- セットや食品の変更後も、追加済みの食事記録が変わらない
- 既存データと既存機能が維持される
- Format、Lint、型チェック、テスト、ビルドが成功する
