# ライブラリ食品の食事追加 実装計画

## 目的

ライブラリに登録した食品を選び、入力済みの内容を確認して食事記録へ追加できるようにする。

## 今回の実装範囲

- ライブラリの食品カードを押すと食事追加画面を開く
- 選択した食品の名前、PFC、カロリー、メモを入力欄へ反映する
- 日付、食事区分、摂取倍率を確認・変更して保存できる
- 保存した食事へ元の食品IDを記録する
- 保存後にToday画面へ移動し、追加した食事と集計を表示する
- 食品の取得中・取得失敗・削除済みを扱う
- 既存の直接入力による食事追加を維持する

## 対象外

- Today画面の食事追加モーダル内から食品を検索・選択する
- 食品を確認せず1タップで即時保存する
- 食品の編集・削除
- 食事記録の編集・削除
- 食品セットの一括追加

## 追加時の仕様

- 食品カードのメニューボタンではなく、カード本体を追加導線にする
- 食品IDをルートパラメータとして食事追加画面へ渡す
- ライブラリから開いた場合の日付は当日、食事区分は朝食を初期値とする
- 摂取倍率は`1`を初期値とする
- 食品に保存されたカロリーを維持するため、カロリーは手動入力として初期化する
- 名前、PFC、カロリー、メモは確認画面で変更可能とする
- 保存時には摂取倍率をカロリーとPFCへ反映する
- `meal_entries.source_food_id`へ選択した食品IDを保存する
- `meal_entries`には保存時点の名前・栄養値・メモを保存し、後から食品が変更されても過去の記録は変えない
- 保存後はToday画面へ移動し、保存対象の日付を表示する

## データ取得とエラー

- FoodRepositoryへIDによる食品取得を追加する
- 食事追加画面はSQLiteを直接呼び出さない
- 食品取得中は入力フォームを表示せず、読み込み状態を表示する
- 食品取得に失敗した場合は再試行と閉じる操作を表示する
- 指定した食品が存在しない場合は、その旨を表示して保存させない
- 保存失敗時は入力内容を維持し、既存の再試行可能なエラーを表示する

## テスト計画

### 食品取得

- IDを指定して食品を取得できる
- 存在しないIDでは`null`を返す

### 食事入力

- 選択した食品の名前、PFC、カロリー、メモが初期表示される
- 食品のカロリーがPFCの計算値と異なっても、保存済みカロリーを維持する
- 摂取倍率が`0.5`、`1`、`2`の場合に、PFCとカロリーを正しく計算する
- 画面で摂取倍率を変更して保存すると、倍率適用後のデータがRepositoryへ渡される
- 保存データへ食品IDを設定する
- 初期値を変更して保存できる
- 直接入力では食品IDが`null`のまま保存される

### 画面遷移とエラー

- 食品カードを押すと、その食品IDを指定して食事追加画面を開く
- 食品取得中、取得失敗、食品なしを区別して表示する
- 取得失敗後に再試行できる
- 保存成功後にToday画面へ移動する

既存の直接入力、食品登録、ライブラリ検索、Today画面のテストも実行し、今回の接続で壊れていないことを確認する。

## 完了条件

- ライブラリの食品を選択して食事記録へ保存できる
- 食品IDと保存時点の栄養情報が`meal_entries`へ残る
- 摂取倍率が保存値へ正しく反映される
- 保存後にToday画面で追加結果と集計を確認できる
- 直接入力による食事追加が引き続き動作する
- 読み込み・食品なし・取得失敗・保存失敗を判別できる
- Format、Lint、型チェック、テスト、ビルドが成功する
- Expo Goで主要操作を確認できる
