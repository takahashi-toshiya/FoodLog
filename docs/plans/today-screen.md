# 今日画面 実装計画

## 目的

選択した日の摂取カロリー、PFC、食事記録を一画面で確認できる「今日」画面をReact Nativeで実装する。

この計画では、ブラウザ版プロトタイプの見た目と情報構成を基準に、今後の食事登録やローカルDB接続の土台となる表示部分を作る。

## 今回の実装範囲

- 「今日の記録」のヘッダーと選択中の日付を表示する
- 前後の日付を含む日付選択欄を表示し、選択日を切り替えられるようにする
- 選択日の摂取カロリー、目標カロリー、残りカロリーを表示する
- たんぱく質、脂質、炭水化物について、摂取量と目標値を表示する
- 朝食、昼食、夕食、間食ごとに食事記録を表示する
- 記録がない食事区分には追加導線を表示する
- 画面下部に「今日」「ライブラリ」「設定」のナビゲーションを表示する
- 食事追加ボタンを表示する
- 仮データを使い、記録がある日と空の日の両方を確認できるようにする

## 今回の対象外

- 食事追加フォームの実装
- 食事の編集・削除
- SQLiteなどのローカルDBへの保存
- 目標値の設定・変更
- ライブラリ画面と設定画面の本実装
- カレンダー画面の実装
- 日付や食事データの永続化
- 円形グラフのアニメーション

対象外のボタンは押せる見た目までとし、未実装の機能を勝手に仮実装しない。

## 画面の状態

### 初期状態

- 端末の今日を選択状態にする
- プロトタイプ相当の仮データを表示する
- 摂取量は食事記録から集計する
- 目標値は仮の固定値を使用する

### 別日を選択した状態

- ヘッダーと日付選択欄の選択状態を更新する
- 選択日に対応する仮データへ表示を切り替える

### 記録がない状態

- 摂取カロリーとPFCを0として表示する
- 朝食、昼食、夕食、間食の各区分に追加導線を表示する
- レイアウトが崩れず、食事追加ボタンを操作できる状態を維持する

## データ設計

最初は画面専用のfixtureを使用する。将来DBへ置き換えやすいよう、表示コンポーネントへ直接仮データを書かない。

```ts
type MealType = "breakfast" | "lunch" | "dinner" | "snack";

type MealEntry = {
  id: string;
  date: string;
  mealType: MealType;
  name: string;
  calories: number;
  protein: number;
  fat: number;
  carbs: number;
};

type NutritionGoal = {
  calories: number;
  protein: number;
  fat: number;
  carbs: number;
};
```

- 日付は端末のタイムゾーンにおける日単位で扱う
- 集計処理はUIから分離した純粋関数にする
- カロリーとPFCはMVPでは整数表示とする
- 目標を超えた場合、残りカロリーは0未満にせず、進捗表示も上限100%とする

## コンポーネント構成案

```text
TodayScreen
├── TodayHeader
├── DateSelector
├── DailyNutritionSummary
│   └── MacroProgressRow
├── MealList
│   └── MealSection
│       └── MealEntryRow
├── AddMealButton
└── AppTabBar
```

### `TodayScreen`

- 選択日を管理する
- 選択日に対応する食事記録を取得する
- 集計結果を各表示コンポーネントへ渡す
- 画面全体のレイアウトを組み立てる

### `DateSelector`

- 表示対象の日付一覧と選択中の日付を受け取る
- 日付が押されたことを親へ通知する
- 食事データや集計処理を持たない

### `DailyNutritionSummary`

- カロリーとPFCの摂取量、目標、残量、進捗を表示する
- 集計処理は行わず、計算済みの値を受け取る

### `MealList` / `MealSection`

- 食事を朝食、昼食、夕食、間食の順に表示する
- 区分ごとの合計カロリーを表示する
- 記録がない場合は追加導線を表示する

### `MealEntryRow`

- 食品・料理名、PFC、カロリーを表示する
- 編集処理は今回持たない

### `AddMealButton` / `AppTabBar`

- プロトタイプにある主要な操作導線を表示する
- 今回は遷移先を実装しない
- 今後Expo Routerへ接続しやすいProps構成にする

小さな装飾だけの要素は独立コンポーネントにせず、責務または再利用性が明確な単位だけ切り出す。

## UI実装方針

- React Nativeの標準コンポーネントを基本とする
- スクロール領域には `ScrollView` を使用する
- セーフエリアを考慮し、端末のノッチやホームインジケーターと重ならないようにする
- 色、余白、角丸、情報の優先順位はプロトタイプを基準にする
- Web固有のCSSや絵文字アイコンはそのまま移植せず、React Nativeで安定して表示できる表現へ置き換える
- iOSとAndroidの両方で成立するレイアウトにする
- 固定の端末幅や高さに依存しない
- アクセシビリティラベルと十分なタップ領域を設ける

## テスト計画

### 集計ロジック

- 複数の食事からカロリーとPFCを正しく合計できる
- 食事が0件ならすべて0になる
- 目標超過時の残量と進捗を安全な範囲に収める

### 画面

- 初期状態で今日の日付と仮の食事記録が表示される
- 食事区分が朝食、昼食、夕食、間食の順で表示される
- 日付を選択すると、対応するデータへ切り替わる
- 記録がない日には各区分の追加導線が表示される
- カロリーとPFCの集計結果が表示される

### 手動確認

- Expo Goで実機表示を確認する
- 小さい画面でもスクロールして全項目を確認できる
- 主要ボタンが端末のセーフエリアと重ならない
- プロトタイプと情報の優先順位が一致している

## 完了条件

- 実装範囲に記載した表示と日付切替が動作する
- プロトタイプの今日画面と情報構成が一致している
- 記録あり・記録なしの状態を確認できる
- 集計処理がUIから分離され、自動テストで検証されている
- `make lint`、`make typecheck`、`make test`、`make build` が成功する
- Expo Goで実機確認できる
- 対象外の機能が実装に混ざっていない

## 実装前に確認する事項

1. 最初の実装に下部タブバーの見た目を含めるか
2. 日付選択はプロトタイプどおり前後5日表示でよいか
3. 円形のカロリー進捗を初回から再現するか、数値表示を先に完成させるか
4. 仮データの日付を固定せず、実行日を基準に生成してよいか
5. 食事追加ボタンを押したとき、今回は無反応にするか「未実装」と表示するか
