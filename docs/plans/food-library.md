# ライブラリ画面 実装計画

## 目的

よく使う食品を一覧で確認し、食品名で絞り込める「ライブラリ」画面をReact Nativeで実装する。

この計画では、ブラウザ版プロトタイプの見た目と情報構成を基準に、今後の食品登録、SQLite保存、食事追加へつながる画面とナビゲーションの土台を作る。

## 今回の実装範囲

- ライブラリ画面のヘッダーを表示する
- 「よく使う食品」と「セット」の切り替え表示を配置する
- よく使う食品を仮データで一覧表示する
- 各食品に食品名、基準量、カロリー、PFCを表示する
- 登録済み食品を食品名で絞り込めるようにする
- 検索結果が0件の場合に空状態を表示する
- 登録済み食品自体が0件の場合に初期空状態を表示できる構成にする
- Today画面とライブラリ画面を下部タブから相互に移動できるようにする
- 「設定」タブは既存どおり未実装のままとする
- 食品追加、食品操作、セット、食事追加につながる導線は、プロトタイプ相当の見た目まで配置する

今回の検索は、端末内に登録済みの食品を絞り込むローカル検索である。外部の商品データベースやWebを検索する機能は含めない。

## 今回の対象外

- 食品の新規登録、編集、削除
- 食品をToday画面の食事へ追加する処理
- 食品詳細画面または確認シート
- セットの一覧、登録、編集、削除
- SQLiteの導入と食品の永続化
- Repositoryの具体実装
- Firestoreなどのクラウド保存と同期
- 外部食品データベース、バーコード、Web検索
- 設定画面の実装

対象外のボタンは押せる見た目までとし、未実装処理や仮の成功通知を追加しない。

## 画面の状態

### 初期状態

- 「よく使う食品」を選択状態にする
- プロトタイプ相当の仮データを一覧表示する
- 検索欄は空にする
- 下部タブでは「ライブラリ」を選択状態にする

### 検索結果がある状態

- 入力された文字列を含む食品だけを表示する
- 検索文字列の前後の空白は無視する
- 英字は大文字と小文字を区別しない
- 食品データ自体は変更しない

### 検索結果がない状態

- 一覧を表示せず、該当する食品がないことを表示する
- 検索を解除できる状態を維持する
- 食品登録済み0件の状態とは文言を分ける

### 登録済み食品がない状態

- ライブラリが空であることを表示する
- 食品追加ボタンを主要な導線として示す
- 検索結果0件の文言は表示しない

### セットを選択した状態

- タブの選択状態だけを切り替える
- セット機能が今回の対象外であることが分かる空状態を表示する
- 仮のセットデータや追加処理は実装しない

## データ設計

初回は画面確認用のfixtureを使用する。食品データをJSXへ直接記述せず、将来Repositoryから取得するデータと同じ型で扱う。

```ts
type FoodItem = {
  id: string;
  name: string;
  servingAmount: number;
  servingUnit: string;
  calories: number;
  protein: number;
  fat: number;
  carbs: number;
};
```

- 数値は負数を持たない前提とする
- カロリーとPFCはMVPでは整数表示とする
- `servingAmount` と `servingUnit` は「1食」「150 g」など栄養値の基準量を表す
- 表示用の文字列を保存せず、食品データから組み立てる
- fixtureは開発・テスト専用であり、将来SQLiteへ初期データとして自動登録しない

## 保存設計の方針

将来の食品登録と永続化ではSQLiteを端末内の正規の保存先とし、画面からSQLiteを直接呼び出さない。

```text
FoodLibraryScreen
        ↓
FoodRepository
        ↓
SQLiteFoodRepository
        ↓
SQLite
```

画面は「どの食品が必要か」だけをRepositoryへ要求し、SQL、テーブル名、SQLiteの接続処理を知らない構成にする。

今回は登録処理がなく、実データを作る方法がないためSQLiteを導入しない。画面と検索の仕様を確定した後、食品登録と合わせてRepository、マイグレーション、SQLite保存を実装する。

## コンポーネント構成案

```text
FoodLibraryScreen
├── LibraryHeader
├── LibraryCategoryTabs
├── FoodSearchInput
├── FoodList
│   └── FoodCard
├── LibraryEmptyState
└── AppTabBar
```

### `FoodLibraryScreen`

- 選択中のカテゴリと検索文字列を管理する
- 食品一覧を検索条件で絞り込む
- 一覧、検索結果0件、初期空状態を切り替える
- 画面全体のレイアウトを組み立てる

### `LibraryCategoryTabs`

- 「よく使う食品」と「セット」の選択状態を表示する
- 選択されたカテゴリを親へ通知する
- 食品やセットのデータは持たない

### `FoodSearchInput`

- 検索文字列を表示する
- 入力変更を親へ通知する
- 検索処理そのものは持たない

### `FoodList` / `FoodCard`

- 食品一覧を表示する
- 食品名、基準量、カロリー、PFCを表示する
- 食品選択とメニューボタンは今後接続できるPropsだけを用意し、今回は処理を持たせない

### `LibraryEmptyState`

- 登録済み0件、検索結果0件、セット未実装の状態を文言で区別する
- 必要な場合だけ食品追加導線を表示する

### `AppTabBar`

- Today画面とライブラリ画面の選択状態を表示する
- Expo Routerを利用して実装済み画面へ移動する
- 各画面がルート文字列やSQLiteへ依存しないよう、ナビゲーション接続はルートまたは共通ナビゲーション境界で行う

小さな装飾だけの要素は独立コンポーネントにせず、実装時の大きさと責務を見て統合してよい。

## ナビゲーション方針

- Expo Routerの`(tabs)` Route Groupにライブラリ用ルートを追加する
- `(tabs)/_layout.tsx`で共通の下部タブを管理する
- ルートの`index.tsx`は`/today`へのリダイレクトだけを担当する
- `src/app/`のルートファイルは画面本体を持たず、`FoodLibraryScreen`を呼び出すだけにする
- Today画面の「ライブラリ」タブからライブラリ画面へ移動できるようにする
- ライブラリ画面の「今日」タブからToday画面へ戻れるようにする
- 同じ画面をタブ移動で積み重ねないよう、タブ移動には履歴を増やさない方式を選ぶ
- 「設定」タブは押しても未実装のままとし、存在しないルートへ遷移させない

## UI実装方針

- React Nativeの標準コンポーネントを基本とする
- 一覧は将来のデータ件数増加を考慮し、`FlatList`を使用する
- キーボード表示中も検索結果を確認できるようにする
- セーフエリアと下部タブの高さを考慮する
- 色、余白、角丸、情報の優先順位はプロトタイプを基準にする
- Web固有のCSSや文字アイコンはそのまま移植せず、React Nativeで安定する表現へ置き換える
- iOSとAndroidの両方で成立するレイアウトにする
- 検索欄、カテゴリ、食品カード、追加ボタンに適切なアクセシビリティ情報を設定する

## テスト計画

### 食品の絞り込み

- 食品名の一部で絞り込める
- 前後に空白があっても同じ結果になる
- 英字の大文字と小文字を区別しない
- 一致しない場合は空配列になる
- 元の食品一覧を変更しない

検索処理を画面内に置く場合は、上記を独立したサービステストにせず、重要な振る舞いだけを画面テストで確認する。

### 画面

- 初期状態で「よく使う食品」と仮の食品一覧を表示する
- 検索文字列を入力すると表示食品が絞り込まれる
- 一致しない検索では検索結果0件の状態を表示する
- 登録済み食品がない場合は初期空状態を表示する
- 「セット」を選択するとセット用の空状態へ切り替わる
- 下部タブでToday画面とライブラリ画面を移動できる

### 手動確認

- Expo GoでToday画面とライブラリ画面を往復できる
- 検索入力、キーボード表示、スクロールが干渉しない
- 小さい画面でも食品情報と下部タブが重ならない
- 長い食品名や基準量でもレイアウトが崩れない
- iOSとAndroidで検索欄とキーボードの表示を確認する
- プロトタイプと情報の優先順位が一致している

## 実装順序

1. FoodItem型とfixtureを追加する
2. 食品の絞り込み仕様を実装する
3. 食品カード、検索欄、カテゴリ切り替えを実装する
4. FoodLibraryScreenで画面状態を組み立てる
5. Expo Routerへライブラリルートを追加する
6. `(tabs)/_layout.tsx`でAppTabBarを相互遷移へ接続する
7. サービスと画面の自動テストを追加する
8. Expo Goで実機確認する

## 完了条件

- プロトタイプ相当のライブラリ画面が表示される
- よく使う食品を一覧で確認できる
- 食品名によるローカル絞り込みが動作する
- 初期空状態、検索結果0件、セット未実装状態を確認できる
- Today画面とライブラリ画面を下部タブから相互に移動できる
- fixtureが表示コンポーネントへ直接記述されていない
- SQLite固有の処理が画面へ混入していない
- Format、Lint、型チェック、テストが成功する
- Expo Goで実機確認できる
- 対象外の機能が実装に混ざっていない

## 次の実装候補

ライブラリ画面の完了後は、次の順で機能を接続する。

1. FoodRepositoryとSQLiteを導入し、食品の新規登録を永続化する
2. 食品の編集・削除を追加する
3. 食品を選択して食事記録へ追加する
4. 食品セットの登録と一括追加を実装する
5. 必要性が生じた場合のみクラウド同期を検討する
